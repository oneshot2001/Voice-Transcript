HTTP API Endpoints

All endpoints are relative to /local/voice/. The web UI uses these endpoints, and they are also suitable for local integration.

Endpoint Method Description
/transcripts GET Recent transcript history (newest first)
Fields include ts, utterance_start_ms, duration_ms, ignored, language, text, keywords
/transcripts DELETE Clear transcript history
/status GET Live runtime status (input, STT, MQTT)
/settings GET / POST Transcription and backend configuration
/mqtt GET / POST MQTT broker configuration and payload metadata
/app GET Application metadata, settings and status snapshot
MQTT Topics

Topics below are logical topics. If a topic prefix is configured in MQTT settings, it is prepended automatically.

Publish (Events from device):
  • connect/{SERIAL}
    Published on startup/shutdown with device info
  • voice/transcription
    Published in Continuous mode for accepted transcripts
  • voice/command
    Published in Voice Commands mode for keyword-matching transcripts
Transcript Payload
{
	  "language": "sv",
	  "text": "turn on the garage lights",
	  "timestamp": 1783527401044,
	  "keywords": ["garage", "lights"],
	  "serial": "B8A44F3024BB",
	  "name": "Lobby Hub",
	  "location": "Building A"
	}
Fields serial, name, and location are appended by MQTT helper settings. In Voice Commands mode, transcripts missing keyword matches are shown as Ignored in UI and are not published.
